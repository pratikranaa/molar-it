Test Jira automation agents against a stateful Atlassian clone — issues, transitions, and sprint fields with Jira REST error shapes.

Clone ID: jira

Connect and test

Best forAgents and test suites that call Jira during checkout, onboarding, or ops workflows.
Connect withRoute mode for your-domain.atlassian.net, or direct REST base URLs from molar clones spawn jira.
Known limitsJira is in launch preview — core REST flows run in isolated sessions; coverage is below public GA and still being measured.
SeedsCommon seeds: empty, enterprise, large-backlog, small-project, sprint-active. Pass --seed to molar clones spawn jira.

What it covers

  • Issue create and transition
  • Project and sprint context
  • Comment and attachment stubs
  • Jira 400/404 error bodies

Available tools

Recorded REST operations. Names match fixture ops in molar-clones — call the equivalent vendor REST path at the clone base URL.

Surface

Use route mode when your app already calls your-domain.atlassian.net. For manual debugging, start the clone with molar clones spawn jira and use the printed REST base URL.

Notes

  • Fixture-replay clone — recorded JSON responses with vendor-shaped status codes and error bodies.
  • Unmatched routes return an explicit unimplemented response instead of proxying to the live vendor.
  • Use the global Molar clones MCP (molar_clone_spawn, molar_clone_seed, molar_clone_route) — fixture clones do not expose per-vendor MCP tool servers.
