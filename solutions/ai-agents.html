MolarQA for AI agents

Let the agent verify the app it just changed.

AI coding agents can write a checkout flow quickly. They also need to use the app and confirm that customers can sign in, pay, and get access. Molar gives agents CLI and MCP tools to run browser tasks, inspect what happened, and try again.

Explore developer tools Read the docs

One command after code

Run molar verify "login works" --url http://localhost:3000 --json and return a structured pass or failure for the next agent turn.

MCP access

Connect an agent to https://api.molar.it/mcp or run the local stdio server through molar mcp serve.

You stay in control

External targets require authorization, and financial or irreversible browser actions pause for confirmation.

Useful output for the next turn

Task status, trace references, a live view link for supported runs, and captured evidence give an agent concrete context to diagnose and rerun. --json keeps the result machine-readable.

  • JSON output
  • Task polling
  • Browser and identity tools

A verification loop with control

After changing a login form, run the local check, read the pass or failure, inspect the cited evidence, and rerun after the fix. Hosted runs use the target and credentials you choose.

Run after a code change
molar verify "login works" --url http://localhost:3000 --json

Give the agent a concrete assertion

Ask for a result it can observe: "show the invoice number", "reach the signed-in dashboard", or "confirm the order says paid." Molar returns the run identity and available evidence for the next turn.

  • Visible business outcomes
  • Trace references
  • Structured failure hints

Have a specific workflow in mind?
Let’s talk it through

Can an agent click a payment button automatically?

It can act on an authorized target, but financial or irreversible steps require a confirmation flow.

Can an agent use a real user's login?

Use a saved test account or credential reference for the site. Supported email and SMS connections provide verification codes without using a customer’s personal inbox.

What happens when verification fails?

The CLI can emit a structured failure with a hint and evidence references so the coding agent can inspect the cause and rerun.
