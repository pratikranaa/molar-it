MolarCoding agents

Your agent writes the change.
Molar checks it in a browser.

Molar opens the app your coding agent just changed, uses it in a real browser, and sends back a result with proof. The agent fixes what failed and checks again. You get the recording.

What you get back
from every run.

The proof comes with the result: to your coding agent in one call, and to you on the run page.

The answer and its proof

The answer Molar found, and the text on the page that backs it up.

Checks on the final page

Each check is marked passed or failed, so you can see what was confirmed.

A recording

A video of the whole run. Watch it live while it runs, or replay it afterward.

A Playwright test you keep

Every passing run leaves a test. Download it, open a pull request into your GitHub repo, or add it to your Molar tests to run on every pull request.

A link to share

Public links are opt-in. Choose Anyone with the link and the person you send it to sees the task, the result, the answer, the proof and the checks, with no sign-up. Including the video is optional.

A verdict when it fails

A failed run is labelled Bug, Flaky or Test drift. For test drift, Molar also gives you a repaired test.

When Molar can’t confirm something, it says so and shows you what it saw.

One call.
A result your agent can act on.

Check after every code change. Edit the login form, check it on localhost, read the result, and run the same check again after the fix. Ask for something you can see, such as “the dashboard shows Welcome, Sam” or “the order says paid”.

The agent runs molar verify with a statement to check and a URL. Molar does the work in a real browser and returns the status, the answer, the checks and a link to the run. If the check failed, error.hint says where to look, and the agent fixes the code and runs it again.

Over MCP, the same check is the molar_verify tool. For a task instead of a statement, such as “find the latest invoice”, use molar run or the molar_run_task tool.

Reviewers see the result
in the pull request.

Guard runs your Molar tests on every pull request and posts one comment: Molar found a problem or Verified by Molar, with a link to the recording. A failure is labelled Bug, Flaky or Test drift, so a reviewer knows whether to fix the app or the test.

Every passing agent run can leave a Playwright test, and you can add it to your Molar tests so it runs on every pull request from then on.

Use test accounts.

Runs open pages only on your project’s hosts. The agent doesn’t pause before a payment or a delete in the browser, so give it accounts and data you can afford to change.

  • A saved test account or credential reference for the site
  • Stripe test mode, or the Stripe clone, for payments
  • Supported email and SMS connections for verification codes, not a customer’s inbox

Can my agent check an app running on localhost?

Yes. The CLI can run the browser on your machine, so it reaches http://localhost:3000. Public URLs can run on Molar’s hosted browsers.

What does my agent get when a check fails?

The failed checks, the answer Molar found on the page, an error.hint that says where to look, and a link to the run with the recording. The run page labels the failure Bug, Flaky or Test drift.

Who can see a run?

Members of your workspace can open it. A run is public only if you choose Anyone with the link on the run page. Including the video in a shared run is optional.

Can my agent use a real user’s login?

Use a saved test account or credential reference for the site. Supported email and SMS connections provide verification codes, so the agent doesn’t need a customer’s personal inbox.

Does the agent need test accounts?

Yes. The agent doesn’t pause before a payment or a delete in the browser, so give it test accounts and Stripe test mode, or the Stripe clone.
