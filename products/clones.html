Connect your test to a service you control.

Start a local clone, configure the test endpoint, and inspect the records your app creates. The SDK handles scoped state and reset controls.

Start Stripe locally

Go installed · from your Clones checkout
cd /path/to/molar-clones
MOLAR_CLONE_ADDR=127.0.0.1:8000 \
MOLAR_CLONE_ADMIN_ADDR=127.0.0.1:9000 \
go run ./cmd/clones-stripe

Run this command from the Clones source checkout supplied during beta setup. The other service binaries are clones-twilio, clones-email, clones-auth, and clones-s3.

Save and restore test state

TypeScript SDK · example test fixture
import { stripe } from '@molar/clones';

const clone = await stripe.start({ seed: 'checkout' });
const before = await clone.snapshot();
await clone.seedData({
  customers: [{ email: 'buyer@example.test' }]
});
await clone.restore(before);
await clone.stop();

Configure your app’s test SDK to use clone.url and the scoped credentials from your setup. This example restores the snapshot, removing the customer created after it.

Have a specific workflow in mind?
Let’s talk it through

What does a Clones run isolate?

Each run gets tenant-scoped service state, including the records created by your test. Deterministic IDs make repeated local and CI runs easier to compare.

Can I test a webhook without weakening signature checks?

Yes, supported webhook paths emit vendor-shaped callbacks with clone-controlled signing secrets. Your application can verify the signature and your test can inspect delivery attempts.

How do I test expiry or renewal without waiting?

Use the virtual clock controls exposed by the clone setup. Advance simulated time to reach supported expiry, delayed delivery, or renewal behavior, then inspect the resulting records.

What is the difference between reset and restore?

Restore loads a saved snapshot of a run’s records. Reset removes the run state so the clone can return to its initial state. Choose the one your scenario needs.

Does the catalog implement every vendor API?

No. Stripe, Twilio, Email, Auth, and S3 each implement documented operations and state transitions. Check the service page and known limits before depending on a behavior outside those paths.

Can I run this in CI or offline?

The repository supports local processes, Docker, and on-prem deployment patterns. Configure the clone endpoint inside the test environment and keep live vendor credentials out of the run.
