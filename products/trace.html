Already running Playwright?

Add this option to your existing config to retain traces for failed tests. Playwright records actions, DOM snapshots, network and console activity; its viewer can inspect them locally.

playwright.config.ts · merge into your existing config
import { defineConfig } from '@playwright/test';

export default defineConfig({
  use: { trace: 'retain-on-failure' },
});
Record a local test and open its saved trace
npx playwright test e2e/checkout.spec.ts --trace on
npx playwright show-trace path/to/trace.zip

Replace the test and trace paths. The first command runs your test; the second opens the saved recording. These are Playwright commands, not a Molar upload.

Inspect a captured Molar run.

  1. Open the run result and check its artifact list.
  2. Use its Trace ID to export a report or compare it with an authorized passing trace.
  3. Keep that ID and the failing assertion with the issue or pull request.
Molar CLI · export and compare
molar trace export TRACE_ID --format markdown --output trace-report.md --json
molar trace diff PASSING_TRACE_ID FAILING_TRACE_ID --json

Use the configured Molar CLI after sign-in, with your Trace API URL and workspace access. Replace all Trace IDs. Export writes a local report; it does not publish a share link. Available formats depend on the captured artifacts.

Missing data is a limit on the investigation.

A missing DOM snapshot does not mean the page never changed. An absent request body may reflect capture settings or redaction. Check what was retained before drawing a conclusion.

Give your coding agent
the relevant part of the run.

Read the events around one step or compare two authorized traces. A focused result is easier to investigate than an entire log dump.

Read the failed request.

molar_read_trace_slice filters captured events by kind and exact step ID. This example requests up to 100 network responses.

MCP · molar_read_trace_slice
{
  "trace_id": "TRACE_ID",
  "kind": "network.response",
  "step_id": "STEP_ID",
  "limit": 100,
  "offset": 0
}

Compare it with a passing trace.

molar_diff_traces compares network, assertion, clone or DOM evidence. Both Trace IDs must be accessible to the connected workspace.

MCP · molar_diff_traces
{
  "trace_a": "PASSING_TRACE_ID",
  "trace_b": "FAILING_TRACE_ID",
  "dimension": "network"
}

Replace the Trace IDs and Step ID with values from your run. These tools read captured data; they do not start a browser or rerun a payment.

answered.

Have a specific workflow in mind?
Let’s talk it through

Does every run include video, network logs, and clone state?

No. The available data depends on the runner, capture settings, and integrations. Inspect the artifact list for the run. An unavailable recording or empty service capture should not be treated as proof that nothing happened.

Does playing a recording run my app again?

No. Playback shows captured media from an existing run. Starting a new browser task or replaying a generated test executes code again and needs its own environment, accounts, and result. Generated clean replay is still under validation in beta.

Can I compare a passing run with a failing one?

The CLI can compare two traces your workspace is authorized to access. Use the same task and comparable starting state to make the differences meaningful. The interactive comparison above uses authored sample data.

Can I use Trace alongside Playwright Trace Viewer?

Yes. Keep Playwright Trace Viewer for your existing recordings. Molar Trace organizes the captured browser steps and available service details for Molar runs. Export formats depend on the artifacts that exist for that run.

What should I include when reporting a failed test?

Include the run ID, selected step, expected behavior, failed assertion, and relevant captured request or service record. Share through a path the recipient is authorized to access, rather than copying credentials or private payloads into an issue.

Can a coding agent inspect the failure?

Molar provides CLI and MCP tools for reading run results and trace details. The agent needs the configured authentication and relevant trace ID. Read the current developer documentation for the available tools.

Will Trace tell me the root cause automatically?

Trace provides the captured details that help you investigate. A failed assertion and preceding request can identify a useful starting point, but they do not by themselves establish the root cause. Review the app behavior and verify any proposed fix.

Can I upload traces from my existing test runner?

Confirm the current integration during beta setup before adding a reporter package. The Playwright setup shown here uses Playwright’s own tracing. It does not install a Molar reporter or automatically upload a trace.

Does Trace promise a fixed retention period or public access?

Retention and artifact availability depend on your workspace setup. Check the policy and the specific artifact before relying on long-term access. Exporting a report does not create a public link.

Can Trace inspect what a browser agent did?

Captured actions, outcomes and available decision summaries help explain the run. These are bounded run records, not a promise to expose a model’s private internal reasoning.

Where do I start with a private application?

Bring a reproducible task, the app environment, and an authorized test account to beta setup. We will confirm the capture and integration paths your workflow needs. You can inspect the public recording above before connecting your app.
