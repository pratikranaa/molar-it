November 2026

Nov 9

ImprovedWebsite & docsBeta terms

Compare Molar with QA Wolf and mabl.

Two new comparison pages, written from each vendor’s own pricing page, and docs that describe what each feature does for you.

  • NewMolar vs QA Wolf and Molar vs mabl, each ending with when to choose which.
  • ChangedGuard runs, on pull requests or on a schedule, don’t count toward the 25 hosted runs a day.
  • ImprovedDeveloper tools lists the fields molar verify --json returns and the statuses a task moves through.
  • ImprovedThe docs are rewritten around what you do and get. Old pages about Molar’s internals redirect to the nearest page.
Nov 8

ImprovedAgent runs

The agent filters and sorts before it browses.

When a site has filter or sort controls, the agent now applies them before reading results, so a goal like “the cheapest plan billed yearly” needs fewer steps.

  • ImprovedSearching a page for text scrolls to the match.
  • NewA new step reads a whole list from the page at once.
  • ImprovedBefore it finishes, the agent scrolls the evidence for its answer into view, so the final screenshot shows it.
Nov 5

FixedAgent runs

Repeat runs replay cleanly.

A replay of an earlier run was sometimes rejected and the steps redone from scratch. Replays now go through, and each replayed step names the element it acted on.

Nov 4

ChangedAgent runs

One agent for every hosted run, and repeat runs without the model.

Every hosted run now uses the agent introduced on October 25; the earlier agent is retired. When you repeat a goal that already passed, Molar replays the verified earlier run without calling the model, and the agent takes over only where the page has changed.

Turn off replay for one task (HTTP API)
curl -X POST https://api.molar.it/api/v1/agent/tasks \
  -H "Authorization: Bearer $MOLAR_TOKEN" -H "Content-Type: application/json" \
  -d '{"url": "https://staging.your-app.com", "goal": "log in and open billing",
       "runtime": {"cache": false}}'
  • RemovedRequests for any other agent_version now return HTTP 422.
  • NewPut {{email}} in a task to get a throwaway inbox for that run, for sign-ups that email a code. It is deleted when the run ends. (Preview)
  • ImprovedA run restarted after a crash never repeats a change it already sent. It ends as failed with uncertain_after_restart instead.
  • NewWhen a page’s own controls don’t work, the agent can read the site’s API instead. Writes through the API need runtime.api_writes (or MCP api_writes). (Preview)

Nov 4

FixedCLI & MCP

28 MCP tools that failed now work, and task webhooks arrive.

Tools for screenshots, reading the screen, locating and filling elements, capturing network traffic, mapping a site, scenarios, skills, and running, repairing and exporting automations returned errors. They now work against hosted runs.

  • FixedA task’s webhook_url was never called. Molar now delivers it, signed, when the task ends.
  • NewMCP tools for batches (one task per free browser), schedules and watches (at most every 5 minutes, 20 per organization). (Preview)
  • NewMCP tools for a disposable email identity: create one, read its messages and one-time codes, and use it to sign up. One exists at a time and each lasts 24 hours. (Preview)

ChangedSecurity & privacy

The API schema is no longer public.

api.molar.it no longer serves its schema or interactive API pages to anyone who asks. The HTTP API itself is unchanged; the docs describe the calls you can make.

Nov 3

NewPreviewAgent runsDashboard

Plan tests from one broad goal.

Ask for “a test plan” or “the whole site” and Molar explores without submitting anything, plans scenarios from what it saw, then runs each one as its own test. On the planning run’s page you choose which scenarios to keep.

  • NewOnboarding, Start exploration and Cartographer coverage use the planner, as do the MCP tools molar_explore_target and molar_generate_scenarios_from_url.
  • ChangedNot in the npm CLI yet. In CLI 0.3.12, molar explore uses a retired flow; explore from the dashboard or MCP until the next CLI release.
Nov 3

ChangedBeta terms

Two hosted runs at a time.

Hosted browsers now run two at a time across Molar, up from one. Further runs wait in a queue and start on their own.

Beta limits
Nov 3

ImprovedExportsAgent runs

Exported tests from signed-in runs sign in first.

A run that started from a saved profile now exports a test that signs in before it does anything else, so it passes on a fresh browser.

  • ImprovedA run that typed two different passwords exports each as its own secret.
  • ChangedExported tests wait at most 30 seconds for each action and 60 seconds for each page load.
  • ImprovedRuns keep the viewport you ask for, such as a 390×844 phone, instead of switching to desktop.
  • FixedA replay refused before it started no longer holds a hosted browser. It had kept other runs, including first runs, queued for up to 20 minutes.
  • FixedThe agent always reports what it found on its last step.
Nov 2

ImprovedExportsDashboard

Exported tests wait for what each action changed.

Instead of fixed pauses, each step in an exported test waits for the change the agent saw: a new URL, an element that appears, or a row that disappears.

  • ImprovedA click that opens a new tab exports as a popup the test follows.
  • FixedA browser error page now counts as a failed load instead of a page.
  • FixedA new account’s first dashboard visit no longer shows errors.

October 2026

Oct 26

NewExportsAgent runs

Exported tests repair themselves when replay fails.

Molar replays every exported test without the agent. If the replay fails, it repairs the test and replays it again. A repair never removes or weakens a check.

  • NewThe agent can upload files, capture downloads and drag elements.
  • ImprovedExported tests use the run’s viewport, dismiss popups that block the page, and wait correctly for slow page loads.

Oct 26

ImprovedSecurity & privacy

Dashboard recordings never capture your run content.

Our product analytics record how the dashboard is used. Those recordings now mask all text and every input, block images and video, drop query strings from URLs, and record no console output.

FixedCLI & MCPTrace

@molar/reporter 0.3.7 uploads to the right address.

In 0.3.6 the default upload address returned 404, so results from your own Playwright or Cypress suite never reached Trace. Upgrade to 0.3.7.

ImprovedWebsite & docs

Pricing, security and setup, in plain words.

A Pricing page with the beta limits and how long data is kept, a Security page that says what we do and haven’t done yet, and developer pages with commands you can copy.

  • NewHosted runs come from one static IP address, published on the Security page so you can allowlist it.
  • New/.well-known/security.txt and a real example run with the test it exported.

Oct 25

NewAgent runs

A new browser agent for hosted runs.

Hosted task runs use a new agent. It checks each step against your goal as it works and can export the run as a Playwright test.

  • NewWhere your task says “verify”, the agent checks it during the run, and the exported test contains the same check at the same point.
  • NewSaved logins ({{username}}, {{password}}, {{totp}}) and protected values are typed only when needed, and only on your project’s hosts.
  • NewSites behind your own bot protection: a project setting makes hosted runs and exported tests send a secret header only to your hosts.
  • ImprovedRuns and their recordings are named after their goal.

Oct 15

NewGuard

The Guard GitHub Action.

Add pratikranaa/guard-action@v1 to a workflow to run a registered scenario on every pull request. Start in advisory mode, then make it a required check.

.github/workflows/molar.yml
- uses: pratikranaa/guard-action@v1
  with:
    api-key: ${{ secrets.MOLAR_API_KEY }}
    scenario-id: checkout
    base-url: https://staging.your-app.com
    mode: advisory
GitHub Actions guide

NewAgent runs

Block ads, and follow your app to other sites.

Ad-heavy pages slow runs and break exported tests. --block-ads blocks well-known ad and consent hosts in the hosted browser and in the exported test.

  • NewThe agent can follow your app to other public sites, such as an OAuth sign-in or a hosted checkout. Private addresses stay blocked.
