Molar · evidence-first verification

One verified run. Five instruments working together.

Map the product, exercise risky paths, control the systems around it, and keep the evidence needed to decide what ships.

Limited The universal five-instrument handoff is a product direction built from working surfaces; it is not yet one uniformly available orchestration across every deployment.

The system

Each instrument leaves the next one better informed.

Cartographer · Current Discovers browser flows, executes goals, and produces a verified map of what it observed.

Trace · Current Preserves screenshots, actions, browser state, and adjudication context so a result can be inspected after the run.

Plumbing · Current Connects identity, projects, runs, CLI, MCP, policy, and billing surfaces; exact availability depends on the product path.

Guard · Limited Uses scenarios for release checks and monitoring where configured. Coverage and deployment behavior remain environment-dependent.

Clones · Limited Provides controlled state for supported payment, messaging, identity, and storage paths. It does not imply a complete clone of every vendor.

The handoff

A receipt should carry more than pass or fail.

Representative evidence packet Limited

Intent

Goal and operating boundary

What Molar was asked to prove, which environment it used, and the safety budget applied.

Observation

Browser and system evidence

Actions, outcomes, screenshots, traces, and configured integration state that support the decision.

Uncertainty

What remains unresolved

Skipped work, expected denials, uncovered branches, and signals the run could not confidently adjudicate.

Limited universal loop Today, evidence moves through several real product surfaces, but the seamless Cartographer → Clones → Trace → Guard → Plumbing handoff remains partial and deployment-dependent.

Decision boundary A verified receipt is evidence for a release decision, not a claim that every state, dependency, or failure mode was observed.
