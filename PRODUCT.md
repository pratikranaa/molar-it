# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users
Software founders, engineering teams and QA teams shipping web applications, especially applications with payments, authentication, email, SMS and other third-party dependencies. A second audience is developers and AI agents needing general browser execution.

## Product Purpose
Molar explores, automates, verifies, monitors and debugs web applications through real browsers. Its complete target connects discovery, verified Playwright, repository delivery, Guard and Mender. Actual availability must be grounded in the monorepo STATUS.md and IMPL_STATUS.md.

## Positioning
Two user-requested marketing versions: general-purpose QA with particular strength in integration-heavy apps at `/`; general browser execution for humans and agents at `/platform`. Third-party service Clones distinguish the QA story. Neither version narrows the actual product scope.

## Operating Context
Teams evaluate Molar before signing up at app.molar.it. Documentation lives at docs.molar.it. Preserve existing functional API handlers, legacy public articles, legal documents, and deep links.

## Capabilities and Constraints
Marketing deployment is the existing Cloudflare Pages molar-it project. Static HTML, CSS and small browser JavaScript are sufficient; avoid a framework migration. Product remains beta. Do not claim unrestricted reliability, fully automated repairs, comprehensive provider support, compliance certifications, guaranteed safety, free allowances, customer counts or performance numbers without evidence.

## Brand Commitments
User requests full, professional, established-product presentation; no AI slop. Inspiration: tester.army, waybill.to, onorca.dev and cloudflare.com. Shared navigation: Platform, Products, Solutions, Resources. User selected direct implementation rather than image mockups. Molar name and existing favicon remain.

## Evidence on Hand
Full user vision attachment, monorepo STATUS.md and IMPL_STATUS.md, current source code and operational evidence. No verified public customer testimonials or case-study metrics supplied. Product demonstrations must be explicitly identified as illustrative.

## Product Principles
- Explain the customer outcome before the component architecture.
- Show specific journeys and observable evidence.
- Keep QA and generalist positioning distinct but connected.
- Publish complete, useful pages and working paths to signup/docs.
- Separate target vision from verified current support.

## Accessibility & Inclusion
Responsive mobile and desktop, semantic HTML, keyboard navigation, visible focus, readable contrast, reduced-motion support.
