Read before comparing

This is not a leaderboard result. We have not submitted it, and no human graded it. The leaderboard’s own grading is a different method from the one we ran.

27 of the 300 runs ended on a bug in the agent’s final check, since fixed; they count as failures. Molar’s own verdict was 210 of 300 and disagreed with WebJudge on 59 tasks. The agent has changed since this build.

How it was run

Each task starts on its own website, in a fresh 1440×900 browser (CloakBrowser) with a 900 second budget. The judge sees the actions and screenshots, not the agent’s final answer.

Read before comparing

We ran the oracle-checklist setting, where the agent is given the benchmark’s checklist. The end-to-end setting, where the agent writes its own checklist, has not been run in full.

The paper reports a best oracle F1 of 49.2 (Claude Sonnet 4.5) and 46.8 (GPT-5.1). That used a different harness, so treat the two as context, not a head-to-head.

How it was run

One agent run per checklist item, each in a fresh browser, with 15 steps and 240 seconds per item. The agent sees screenshots; the paper’s baseline reads the page structure only. It finds more problems than the gold labels list, which costs precision.

How we run evals.

The same rules apply to every number on this page.

Real browsers

Runs drive a real browser through Playwright. Public-site tasks run on the live sites, so they change as the sites change.

A fresh session for every task

Each task starts in a new browser context, so one task can’t leave state behind for the next.

No per-site rules

The agent gets the task and the page. When a site beats it, we change how the agent works, not add a rule for that site.

The judge is separate

A grader that is not the agent decides pass or fail, with each benchmark’s own method where it has one. The agent’s own verdict is recorded but does not count.

False passes are the worst outcome

A false pass is a run where the agent says it succeeded and an independent check says it did not. A QA tool that does this can’t be trusted, so the release gate allows none.

Every deploy is gated

Before an agent build goes live it runs the 39-task hosted eval. It needs at least 90% and zero false passes.

A task with no result counts as a failure. When we rerun tasks that failed on infrastructure, we show the score from before the rerun.

Reproduce it.

Every benchmark here is public. Run your own agent, or ours, through the same grader.

Why are your scores lower than the ones other companies publish?

Some are, and we show them. Published scores often use a different judge, a patched task list or a longer time budget, and some are self-reported. We use the benchmark’s own grading where it still works, and say where we could not.

Why GPT-6 Luna as the judge?

WebVoyager’s original judge, GPT-4V, is retired, and Online-Mind2Web’s repository now points to GPT-6 Luna for WebJudge. We kept each benchmark’s prompts unchanged and changed only the model.

Do these scores predict how Molar does on my app?

Not directly. They measure a general browser agent on public tasks. The hosted regression eval is closer to what Molar does for you, but it is also our own test set. The best check is a run on your app.

How often does this page change?

When we rerun a benchmark. Each row shows the date of its run and the agent build.
